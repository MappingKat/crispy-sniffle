01 Receipt #1 · The work that maps to this role

Customer identity at scale — I've done this exact shape.

At Lytics I led a Whirlpool engagement that's the closest analog I've shipped to what Trimble is hiring for. The customer data lived in a relational SQL stack — transactions, products, customers, devices, web events — and the job was to translate that into a graph identity model: persons, households, devices, and accounts as nodes, with edges expressing the relationships between them.

It's the same primitives an MDM platform asks you to configure — just instantiated in a different vendor's runtime.

  • Deterministic + probabilistic matching. Tiered-confidence model — high (same email + same device fingerprint + same IP), medium (household cluster, keep distinct but link), low (don't merge).
  • Survivorship rules. Last-touch wins on contact fields, source-of-truth for transactional fields, manual override for stewardship cases.
  • Cross-reference patterns. Mapped Whirlpool's source-system IDs to a canonical graph identity. Bidirectional sync so each upstream system stayed in lock-step.
  • Hierarchy management. Household → person → device. Edges scored by confidence, hierarchy queryable for downstream marketing and service.
  • Stewardship-friendly outputs. Every segment built off the graph could be traced back to the identity links and confidence scores that built it. The marketing team could explain any number to leadership.

Scale was tens of millions of records, multi-vendor data sources, and an ongoing event stream. The exact failure modes you'd see in an enterprise MDM rollout — false-positive merges from shared IPs, hierarchy drift, source-of-truth conflicts, stewardship escalation paths — I've already debugged in production.

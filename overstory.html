02 How I'd run a customer engagement

Pattern I'd apply, in four moves.

01 · Clean + classify the dataset

Run the satellite imagery through the pipeline. Validate the output. Surface the missing reads, the unit mismatches, the classification edge cases. Document every assumption — that documentation IS part of the deliverable when a utility VP asks "where did this number come from?"

02 · Translate, don't dump

The output is not a notebook. The output is "here are the three corridors that earn an attention budget next quarter." Lead with the decision the vegetation manager needs to make. Unfold the methodology only as deep as the audience wants.

03 · Listen for the recurring ask

Every third or fourth customer request is the same shape. That's a product feature waiting to be born. I'd flag it to product + engineering with a concrete proposal — not a wish-list, a sketch.

04 · Refactor the notebook → script → tool

The boring infrastructure work. Versioned scripts, clean handoffs, README-first engineering. The team-doubling secret is making sure today's one-off doesn't become tomorrow's debugging session.
